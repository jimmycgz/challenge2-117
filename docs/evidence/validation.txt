What it told us and what we did
--------------------------------------------------------------------------------
1. Sealed goods keep their clock (FAIL). The table says 48 cases of sealed infant formula, 8 months to expiry, have 1 hour left,
  because the snapshot matched it to FoodKeeper's prepared-formula row (pantry 1.0 hours, refrigerated 24.0 hours).
   - The agent does not read hours_remaining from this table. Its instructions (agent.py, step 2) have it call
     lookup_shelf_life, take the smaller of the donor's deadline and the shelf life, and trust the donor's figure when the
     result has a caution or the posting says the product is sealed or gives its own expiry.
   - lookup_shelf_life returns the exact FoodKeeper name match first. Run against these tables, lookup_shelf_life("Formula",
     "pantry") returned 1.0 hours with a caution, and lookup_shelf_life("Formula", "refrigerated") returned 24.0 hours with no
     caution.
   - _shelf_caution adds that caution to any figure of 2 hours or less. Its text says the figure is probably for an opened or
     prepared container, and to use the donor's figure if the posting says sealed or gives its own expiry.
   - So the code catches the 1-hour pantry figure. The 24-hour refrigerated figure carries no caution, and there the only guard
     is the 'sealed' rule in the prompt, not code.
   - Our scripts that do read the table clock (equity_audit.py, and check_invariants.py through it) override posting 8 to 168
     hours with CLOCK_OVERRIDE = {8: 168} and print both figures. demo_tracks.py uses 168.

2. Text matches flags (FAIL, 2 rows). Our hard filter, apply_constraints in tools.py, reads the cold_storage column and never
  the profile text, so it believes the flag.
   - Lakeshore Mutual Aid Collective (flag none, text describes chilled holding) is removed from every cold load as "no cold
     storage". That is a missed recipient, not a bad match.
   - Third Ward Community Table (flag walk-in, text says "We have a fridge") stays viable for cold food. We ran
     apply_constraints on its row: a 2-pallet cold load with 24 hours left keeps it as "walk-in cold storage, takes up to 3
     pallets". A 0.5-pallet load with 6 hours left removes it, but only because it needs 12 hours to collect.
   - With the notebook's intended flag, 'domestic', the filter would remove it for any load over 1 pallet
     (DOMESTIC_FRIDGE_PALLETS = 1). As loaded, it is a bad match the filter cannot catch.
   - tools.py has no planted-row filter, so the live agent can return either one. demo_tracks.py labels planted rows "[invented
     teaching case]", and equity_audit.py leaves all nine out. We have not changed the filter; this file records the gap.
